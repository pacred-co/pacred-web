## 2. ทำไมระบบเราติดตู้ผิด

`commitMomoRowCore` ประทับ `fcabinetnumber` **ค่าเดียวให้ทั้งครอบครัว** (base + ลูก `-N`)
แต่ MOMO **แยกส่งชิปเม้นเดียวกันหลายตู้จริง** (ของไม่พอตู้/ปิดตู้ทัน) → แถวที่ไปตู้อื่นติดตู้ผิด.

ผลกระทบ 3 ทาง:
1. **ใบวางบิล MOMO บล็อกการบันทึกต้นทุน** — ใบระบุ `GZS260710-1` ระบบผูก `GZS260712-1`
   → `cabinetConflict` → แถวนั้นบันทึกต้นทุนไม่ได้ (owner เห็นเป็น "🔴 ตู้ไม่ตรง")
2. **กำไรรายตู้เพี้ยน** — ตู้หนึ่งบวมด้วยของอีกตู้ (รายงานกำไรตู้/รายเดือน อ่านผิดทั้งคู่)
3. เคยเป็นต้นทางของบั๊ก **aggregate-fanout ฿880k ผี** (2026-07-20) เพราะ MOMO Live
   คืนยอด Σ ของทั้ง 3 ตู้มาให้แถวเดียว

## 3. กฎ map/match (SOT · `lib/admin/momo-container-truth.ts` · 16 เทส)

```
แถวย่อยของ base เดียวกัน
   └─ จัดกลุ่มตาม momo_container_no (รอบขนส่ง MOMO — MOMO จัดให้แล้ว เชื่อได้)
        └─ เทียบแต่ละกลุ่มกับ "บรรทัดของ base นี้" ในแพคกิ้งลิสแต่ละตู้
             ด้วย 3 ค่า: จำนวนแถวย่อย · Σ น้ำหนัก · Σ คิว
                 ├─ ตรงตัวเดียว  → ตู้นั้นแน่นอน
                 ├─ ตรงหลายตัว   → ambiguous (ให้คนดู — ห้ามเดา)
                 └─ ไม่ตรงเลย    → unmatched  (ให้คนดู)
```

ลำดับความเชื่อ: `container_batch_no` ที่ MOMO ส่งมาเอง (ถ้าอยู่ในแพคกิ้งของ base นั้น) →
จำนวนแถว+น้ำหนัก+คิว → น้ำหนัก+คิว. **ตู้เดียวในแพคกิ้ง = ไม่ต้องเทียบ** (ไม่มีทางเลือกให้ผิด).
tolerance: น้ำหนัก ±0.6 kg · คิว ±0.02 (MOMO ปัดเศษระหว่างไฟล์กับ API ต่างกันเล็กน้อย).

## 6. งานที่เหลือ / ของที่ต้องรู้

- **แพคกิ้ง 40 ไฟล์ค้าง `uploaded`** = อัพไว้แต่ไม่เคยกด "ยืนยัน + อัปเดต" (ไม่ใช่บั๊กข้อมูล
  แต่เป็นคิวงาน) · บั๊กที่แก้แล้ว: การประทับ `applied` เคยกวาดทุกไฟล์ของตู้นั้น
  (ไม่มี `.limit(1)`) → ประวัติบอกไม่ได้ว่าไฟล์ไหนถูกใช้
- **แพคกิ้ง snapshot มีแถวขยะ `Tracking`** (หัวคอลัมน์หลุดเข้ามาเป็น baseTracking 1 แถว)
  — ไม่กระทบ (ไม่มี staging จับคู่ → ถูกข้าม) แต่ควรกันที่ parser
- เลขตู้บน**ใบวางบิล** = ความจริงเดียวกับแพคกิ้ง → ตอนนี้ที่ระบบตรงแล้ว
  `cabinetConflict` ควรหลุดเอง ⇒ กดบันทึกต้นทุนได้
- ทางเขียน `fcabinetnumber` ของ apply แพคกิ้งเคย **ข้าม `cabinetWriteGuard`**
  (เช็คแต่ tier ไม่เช็ค `fcabinet_locked`) → แก้แล้ว
- **การป้องกันไปข้างหน้า:** apply แพคกิ้งจะ**ไม่**ประทับเลขตู้จากหัวไฟล์ทับแถวที่ SOT บอกว่า
  อยู่ตู้อื่น (กัน re-poison ของที่ data-fix เพิ่งแก้)
